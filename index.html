Instructions

Set up HetznerWatch step by step, then learn how to read every availability graphic.

In this guide
  1. Start HetznerWatch
  2. Connect the Hetzner API
  3. Choose monitoring targets
  4. Read the dashboard timeline
  5. Read the long-term charts
  6. Configure ntfy notifications
  7. Operate and update the installation

1. Start HetznerWatch

Docker Compose starts the application and its persistent SQLite volume. No .env file is required.

  1. Install Docker Desktop or Docker Engine with Docker Compose.
  2. Open a terminal in the HetznerWatch project directory.
  3. Build and start the service: docker compose up -d --build
  4. Open the local dashboard: http://localhost:8080

2. Connect the Hetzner API

HetznerWatch only needs a read-only token to load the server catalog and availability information.

  1. Open your project in Hetzner Cloud Console.
  2. Open Security → API Tokens and choose Generate API Token.
  3. Select Read permission, create the token and copy it immediately.
  4. Open Settings → Hetzner Cloud API token in HetznerWatch and paste the token.
  5. Click elsewhere after pasting. The status at the top confirms the automatic save, and the first availability check starts immediately.

The token is stored in the local SQLite database and is never returned to the browser. Leave the field empty later to keep the stored token.

Official documentation

3. Choose monitoring targets

The separate Monitoring tab controls both the check interval and the server/location combinations shown on the dashboard.

  1. Open Monitoring.
  2. Set an interval between 10 and 86400 seconds.
  3. Reload the catalog after adding or replacing the Hetzner token.
  4. Select every server type and location pair you want to observe.
  5. Changes are saved automatically. Wait for the Saved status, then return to the dashboard.

One checkbox represents one target, for example CX23 in fsn1. A yellow Recommended label is Hetzner's location recommendation, not a guarantee of availability.

4. Read the dashboard timeline

The dashboard shows the current state first and the individual checks below it.

  • The summary shows the number of targets, the active interval and the time of the latest check.
  • Each target header shows its server type, location, current state and latest timestamp.
  • The History selector controls how many recent checks are visible.

How to read the box timeline

Each box is one check. Time runs from the oldest check on the left to the newest check on the right. Hover or focus a box to see its exact time, result and any HTTP error.

5. Read the long-term charts

Long-term monitoring groups successful measurements into time buckets. Select 24 hours, 7, 30 or 90 days to change the aggregation.

Summary values and thin lines

  • Servers & locations counts the catalog combinations included in the view.
  • Data coverage shows how much of the selected target/time grid contains measurements.
  • Historically available is the availability share across successful checks.
  • Currently available compares targets available now with all observed targets.
Example: an improving metric line
OlderNewer

Read the thin line from left to right. A rising line means the displayed metric increased; an interruption means that bucket has no usable measurement. The large number remains the primary value.

Availability bars by location

Each bar is one time bucket. Its height is the percentage of successful checks in which the server was available at that location.

Example: changing availability by time bucket
OlderNewer

A tall green bar means high availability, a red baseline means 0%, and a gray baseline means no data. The labels Often, Sometimes, Rarely and Never summarize the percentage for the complete selected range.

Long-term values describe past observations only. They do not guarantee that Hetzner will have capacity when you order.

6. Configure ntfy notifications

HetznerWatch preconfigures the public ntfy server and a random topic. Notifications remain disabled until your phone is subscribed.

  1. Install the ntfy app on Android or iPhone.
  2. Under Settings, copy the generated topic beginning with hetznerwatch_.
  3. In the app, add a subscription on https://ntfy.sh and paste that exact topic.
  4. Enable ntfy in HetznerWatch. The change is saved automatically.
  5. Choose Send test message and confirm that it arrives on the phone.

Anyone who knows a public topic can read or publish to it. Keep the generated topic private. The dashboard link must also be reachable from your phone.

Smartphone guide

7. Operate and update HetznerWatch

  • Follow runtime messages with docker compose logs -f.
  • Restart the service with docker compose up -d.
  • After pulling an update, rebuild with docker compose up -d --build.
  • Settings, secrets and history live in the SQLite database inside the named Docker volume.
  • Back up the volume before replacing the installation and protect the dashboard before exposing it to a network.
